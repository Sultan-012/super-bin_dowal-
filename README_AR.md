# سوبر ماركت بن دول - إصدار المراجعة 2.4

تطبيق ويب عربي RTL لإدخال الورديات ومراجعتها، بعملة الريال اليمني YER. الواجهة React + TypeScript والخادم FastAPI وقاعدة التشغيل PostgreSQL. لا تحفظ المعاملات في المتصفح. هذا إصدار مرشح للاستخدام بعد إتمام الفحص على جهازك وربط مزودي الإشعارات؛ نتائج الفحص الفعلية في `docs/RELEASE_AUDIT_2_4_AR.md`.

## الوظائف الحالية

- الموظف: إجمالي مبيعات جهاز المحاسبة وتاريخه، الإيداع ورقمه وتاريخه، فواتير مشتريات متعددة باسم المورد والتفاصيل والقيمة، أصناف خارج الجهاز باسم ورقم وعدد وقيمة، تحويلات بنكية لفواتير نفس الوردية باسم الشخص والمرجع والقيمة، وملاحظة. رقم فاتورة الشراء والمرفق اختياريان وفق تحديث 2.1، واسم المورد والتفاصيل مطلوبان.
- بعد التسليم تختفي البيانات، ولا يستطيع الموظف استرجاع ورديات أو تقارير عبر الواجهة أو API. إعادة طلب غير مؤكد تستخدم المفتاح نفسه دون تكرار.
- المدير: كل الورديات، التفاصيل للقراءة، التصحيح بسبب موثق ونسخة جديدة، الاعتماد الإداري بمربع تأكيد، الأرشيف حسب تاريخ الجهاز، تقارير PDF وCSV، المستخدمون، سجل التدقيق والإشعارات. حذف حساب يعطّل الوصول ويحفظ سجلاته.
- تشمل الواجهة الوضع الليلي وإظهار كلمة المرور وفواصل الآلاف. كلمة المرور 8 خانات أو أكثر، وتقبل الأرقام فقط إذا اخترتها؛ لا توجد كلمة مرور افتراضية.

**المعنى المالي:** قيمة الصندوق = إجمالي مبيعات الجهاز. الاعتماد الحالي إداري دون جرد نقدي أو إدخال شبكة، كما في تحديث 2.2؛ لذلك لا يحسب عجزًا أو فائضًا للورديات الجديدة. رسوم الفروقات تعرض الجرد النقدي التاريخي المعتمد فقط، وتعرض «لا يوجد جرد» عند غيابه. احتساب فروقات جديدة يحتاج إعادة توفير بيانات الجرد ووسائل السداد ضمن تغيير مستقل. الديون والمطابقات القديمة محفوظة في القاعدة، لكن إدخالها ومساراتها السابقة متوقفة وفق آخر تحديث.

## تشغيل Windows لأول مرة

الأوامر من Terminal في VS Code باستخدام PowerShell. افتح مجلد **Bin_Doul_Financial_System الذي يحتوي README_AR.md وbackend وfrontend**؛ لا تعمل من مجلد التنزيل الخارجي أو من backend إلا عند ذكر ذلك.

1. ثبّت Python 3.12 إصدار 64-bit مع Python Launcher، وNode.js 22.12+ أو 24، وPostgreSQL 17 مع أدوات سطر الأوامر. pgAdmin واجهة إدارة اختيارية؛ تثبيته وحده لا يثبّت خادم PostgreSQL. تحقق:

```powershell
py -0p
py -3.12 --version
node --version
npm --version
```

إذا ظهر `No suitable Python runtime found` فأكمل تثبيت Python 3.12 وأعد فتح VS Code قبل المتابعة. لا تنشئ `backend\backend\.venv`.

2. من جذر المشروع نفّذ:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\scripts\setup-windows.ps1
```

ينشئ بيئة `backend/.venv` عند غيابها، ويثبّت المتطلبات ويبني الواجهة. ينشئ `.env` ومفاتيح عشوائية فقط إذا لم يوجد `.env` مسبقًا. لا يغيّر إعداداتك القائمة ولا ينشئ قاعدة بيانات. يمكنك تثبيت حزم الاختبار بإضافة `-Development`.

3. افتح pgAdmin، واتصل بخادم PostgreSQL، ثم من Databases أنشئ قاعدة باسم `bin_doul` مستقلة. احتفظ بقاعدة التشغيل الحالية إذا كانت موجودة؛ لا تنشئ فوقها أو تسقطها. للتشغيل المحمي يفضّل دور مالك مخطط مستقل ودور تطبيق محدود كما في الخطوة 7.

4. افتح `.env` محليًا. غيّر `DATABASE_URL` إلى اتصال قاعدة المتجر بحساب مالك المخطط وقت التهيئة، مثل القالب التالي مع استبدال القيم محليًا:

```dotenv
APP_ENV=development
DATABASE_URL=postgresql+psycopg://YOUR_DB_OWNER:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/bin_doul
COOKIE_SECURE=false
NOTIFICATION_CHANNELS=
```

لا تنسخ كلمات المثال حرفيًا. إذا احتوت كلمة مرور الاتصال على `@` أو `:` أو `/` أو `#` أو `%` فيلزم ترميزها URL داخل رابط الاتصال. استخدم محرر `.env` محليًا؛ لا ترسل الملف أو كلمات المرور لأحد. أبقِ المفاتيح العشوائية التي ولّدها سكربت الإعداد. التطوير المحلي هنا على الجهاز نفسه فقط.

5. نفّذ الترحيلات من الجذر:

```powershell
.\scripts\migrate-windows.ps1
```

أحدث ترحيل هو `20261030_04`. استخدم **shift_alembic.ini**؛ ملفات SQL Server القديمة ليست جزءًا من التشغيل الحالي.

6. أنشئ المدير الأول، مع إدخال اسم المستخدم والاسم وكلمة المرور وتأكيدها تفاعليًا:

```powershell
Push-Location backend
.\.venv\Scripts\python.exe -m shift_app.cli create-admin
Pop-Location
```

7. بعد الترحيلات، أنشئ دور `bin_doul_app` مع كلمة مرور خاصة عبر pgAdmin، ثم نفّذ `docs/postgres-runtime-permissions.sql` بحساب المالك. غيّر `DATABASE_URL` في `.env` إلى حساب التطبيق. لا تمنحه Superuser أو ملكية المخطط. ثبت نجاح الدخول قبل المتابعة. استعمل حساب المالك مؤقتًا للترحيلات المستقبلية فقط.

8. انقر `Start_BinDoul.cmd` أو نفّذ:

```powershell
.\scripts\start-windows.ps1
```

اترك نافذة الخادم مفتوحة وافتح http://127.0.0.1:8000 وسجّل الدخول بالمدير الذي أنشأته. ينشئ المدير الموظفين من صفحة المستخدمين. الإيقاف بـ Ctrl+C؛ إغلاق الصفحة لا يحذف البيانات.

## تحديث تثبيت قائم

أوقف الخادم وn8n وخذ نسخة احتياطية متحققًا منها من قاعدة البيانات والملفات. فك هذه النسخة في **مجلد جديد**، ثم انقل `.env` المحلي بعد مراجعته دون عرضه أو تضمينه في ZIP. لا تنقل قاعدة تجريبية إلى الإنتاج. يمكنك إعادة تثبيت الحزم داخل مجلد النسخة الجديدة ثم تشغيل الترحيلات بحساب المالك على نسخة مستعادة أولًا. لا تستبدل قاعدة PostgreSQL ولا تستخدم downgrade لحذف البيانات.

```powershell
.\scripts\setup-windows.ps1
.\scripts\migrate-windows.ps1
Push-Location backend
.\.venv\Scripts\python.exe -m alembic -c shift_alembic.ini current
Pop-Location
```

يجب ظهور `20261030_04 (head)`، ثم أعد الاتصال بحساب التطبيق المحدود وشغّل النسخة. لا تنشئ مديرًا جديدًا إن كان حسابك موجودًا. افحص الأرصدة والورديات القديمة، ثم احتفظ بالنسخة السابقة للرجوع إلى نسختها الاحتياطية إذا لزم. الملفات القديمة الزائدة باقية بانتظار موافقتك المحددة في `docs/DELETION_REVIEW_AR.md`؛ لا تشغّلها.

## الاختبارات وإعادة الفحص

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements-shift-dev.txt
Push-Location backend
.\.venv\Scripts\python.exe -m pytest shift_tests -q
Pop-Location
npm --prefix frontend test
npm --prefix frontend run build
node n8n/verify_workflows.cjs
```

تستخدم الاختبارات الافتراضية قواعد SQLite فعلية مؤقتة منفصلة؛ ليست قاعدة تشغيل. لا تشغّل سكربت `prepare-v2_2-tests.py` القديم. لفحص PostgreSQL أنشئ قاعدة اختبار فارغة مستقلة يبدأ اسمها بـ `bin_doul_test`، وعيّن `TEST_POSTGRES_URL` و`BIN_DOUL_TEST_BACKEND=postgres` في جلسة الاختبار فقط. ينشئ الفحص مخططات معزولة ويحذف مخططات الاختبار التي أنشأها. لا توجه متغيرات الاختبار إلى قاعدة التشغيل.

## الربط والنسخ والأمان

- تعليمات n8n والقوالب والـ Credentials في `n8n/README_AR.md`. يرسل التقارير إلى المدير المحدد لكل موظف، ولا توجد رسائل لتحصيل العملاء. تظل ملفات الاستيراد غير مفعّلة حتى ضبط حساباتك واختبارها.
- النسخ والاستعادة في `docs/DATABASE_2_4_AR.md`. المرفقات داخل القاعدة، فتشملها النسخة الاحتياطية. سكربت الاستعادة يعمل على قاعدة جديدة فقط ويلغي جلساتها ويوقف مهام الإشعار للمراجعة.
- العينة منفصلة باسم يبدأ بـ `bin_doul_sample`؛ راجع `sample-data/README_AR.md`. لا ينشئ التشغيل أي بيانات تجريبية تلقائيًا.
- للاستخدام من أجهزة أخرى أو عبر الإنترنت، اضبط HTTPS وخادمًا عكسيًا أولًا، ثم `APP_ENV=production` و`COOKIE_SECURE=true` وأصول `ALLOWED_ORIGINS` الدقيقة. الإنتاج يرفض Cookies غير الآمنة. لا تعرض PostgreSQL أو المنفذ الداخلي للإنترنت. لم تُنشر هذه النسخة خارجيًا.
- مرجع الحساب الحالي: `docs/FINANCIAL_RULES_2_4_AR.md`، ومرجع API الحالي: `docs/API_2_4_AR.md`. ملفات التوثيق ذات الإصدارات الأقدم مراجع تاريخية وليست تعليمات تشغيل 2.4.

المتطلبات المثبتة في الفحص: Python 3.12.14 وNode 24.22.1 وPostgreSQL 17.11. لم ينفّذ مثبت Windows أو Docker أو خادم HTTPS فعلي في بيئة الفحص؛ راجع تقرير النتائج قبل اعتماد تشغيلك.
