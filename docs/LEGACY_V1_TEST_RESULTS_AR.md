## قاعدة الاختبار وحدود الاستنتاج

الاختبارات المحلية طبقت ترحيلات Alembic على **ملفات SQLite مؤقتة فعلية** مع المفاتيح الخارجية والفهارس والقيود، واستعملت مسارات التطبيق الحقيقية. لا يُستعمل تخزين ذاكرة بدل القاعدة، ولا توجد عملية كتابة إلى قاعدة تشغيل المستخدم.

قواعد الإنتاج والتطوير لا تقبل SQLite؛ تقبل SQL Server عبر pyodbc فقط. نجاح اختبارات التزامن في SQLite لا يثبت سلوك أقفال SQL Server. اختبار SQL Server الحقيقي موجود ومشروط باتصال إلى قاعدة جديدة وفارغة باسم ينتهي بـ `_acceptance_test`.

لم يُشغّل ذلك الاختبار لأن البيئة لا توفر خادم SQL Server أو اتصالًا به أو Docker. حزمة pyodbc موجودة، لكن محاولة تحميلها في هذه البيئة أعادت:

```text
ImportError: libodbc.so.2: cannot open shared object file
```

إذًا لم تُختبر هنا: الترحيلات داخل SQL Server نفسه، أو صلاحيات الحساب المحدود عليه، أو النسخ الاحتياطي والاستعادة الفعليان. تم توليد SQL كامل بلهجة MSSQL بنجاح في الوضع غير المتصل، بما في ذلك DECIMAL(18,2)، والنص العربي، والفهارس الفريدة المفلترة، وTriggers اللقطات والتدقيق. هذا فحص توليد، وليس تنفيذًا على الخادم.

## الواجهة والاعتماديات

- نجح `npm run build`، الذي يشغل فحص TypeScript ثم بناء Vite 7.3.7. ملفات الواجهة الجاهزة موجودة داخل `frontend/dist` في الحزمة، إلى جانب المصدر.
- نجح `python -m compileall -q app migrations`.
- نجح `pip check` دون تعارض اعتماديات.
- فحص `pip-audit -r requirements.txt` أظهر **صفر تنبيهات معروفة** في الاعتماديات المثبتة وفق قاعدة الفحص وقت التنفيذ.
- فحص `npm audit --json` أظهر **صفر تنبيهات معروفة** في اعتماديات الواجهة والتطوير. ثُبّت esbuild 0.28.1 بتجاوز صريح متوافق مع نطاق Vite.
- نواتج فحص الاعتماديات الخام في `python-dependency-audit.json` و`frontend-dependency-audit.json`. الفحص لا يضمن انعدام العيوب غير المعروفة.
- تعذرت مراجعة المتصفح: بيئة المعاينة المنفصلة لم تحتوِ Python مع اعتماديات FastAPI/Uvicorn. المحاولات انتهت قبل تشغيل التطبيق، ثم أُوقفت المعاينة. **لا ندعي اختبار تفاعلات الواجهة أو مظهر الهواتف أو الطباعة عبر متصفح فعلي.**
- لم يُختبر التنفيذ على Windows نفسه؛ تعليمات Windows ومتطلبات SQL Server مرفقة ويجب إجراء اختبار التشغيل والاتصال عليها.
- لم تُنشأ خدمة مستضافة أو عملية نشر خارجية.

## خطوات التحقق على جهاز التشغيل

1. أنشئ قاعدة SQL Server فارغة خاصة بالاختبار، وثبّت ODBC Driver 18.
2. شغّل اختبار SQL Server الاختياري وفق README.
3. شغّل التطبيق بقاعدة Sample منفصلة، واختبر الإدخال والتحصيل والمشتريات والجرد والإغلاق والمستخدمين من المتصفح.
4. اختبر الشاشات على الهاتف والطباعة وملف CSV.
5. نفّذ نسخة SQL Server احتياطية واستعادة تجريبية، ثم تحقق من آخر جلسة وكشف عميل.
6. استخدم قاعدة التشغيل الحقيقية بحساب محدود الصلاحيات واتصال HTTPS بعد نجاح ما سبق.
