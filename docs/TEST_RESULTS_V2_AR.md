# نتائج التحقق الفعلية — الإصدار 2

التاريخ: **29 أكتوبر 2026**. المشروع: **سوبر ماركت بن دول**. تخص النتائج أدناه تطبيق `shift_app` وواجهة `src/shift` وقاعدة PostgreSQL المستهدفة، ولا تخص تقارير التحقق القديمة للإصدار الأول.

## الاختبارات المنفذة

| الفحص | النتيجة الفعلية |
|---|---|
| `python -m pytest -q` من `backend`؛ المسار الافتراضي `shift_tests` | **44 ناجحًا، 1 متخطى، وتحذيران** في 20.43 ثانية في آخر تشغيل |
| `npm --prefix frontend run build` | نجح فحص TypeScript وبناء Vite 7.3.7؛ ملفات التشغيل داخل `frontend/dist` |
| `npm --prefix frontend test` | **10 فحوص ناجحة** للدوال الفعلية لتنسيق الإدخال والمبالغ والتواريخ |
| `node n8n/verify_workflows.cjs` | نجح فحص JSON وروابط العقد و**31 تعبيرًا** وتنسيق المبالغ الكبيرة دون تقريب ثنائي |
| Alembic `upgrade head --sql` بلهجة PostgreSQL | نجح توليد `docs/postgresql-v2-schema.sql` دون اتصال بالخادم |
| PDF من قاعدة عينة محفوظة على القرص | صدر تقرير فترة من صفحتين وتفصيل وردية من صفحتين؛ روجعت الصفحات الأربع بصريًا بعد تحويلها إلى صور |

استُخدم Python **3.12.14** وNode **24.22.1**. ناتج pytest الخام في `test-results-v2.txt`. تحذيرا pytest يتعلقان بتقادم واجهات TestClient/HTTPX وAnyIO، ولم يسقط أي اختبار بسببهما. لا يوجد فحص أمني شامل أو ضمان بخلو الاعتماديات من الثغرات في هذا الإصدار؛ تقارير تدقيق الإصدار الأول محفوظة باعتبارها مواد تاريخية فقط.

## ما تغطيه اختبارات الخادم

- الحساب باستخدام Decimal، العجز والفائض والتطابق، الجرد الفارغ مقابل الصفر، رفض السالب والتجاوز والدقة غير الصالحة. لا تستطيع المبيعات خارج الجهاز إخفاء مبيعات جهاز نقدية سالبة.
- إلزام أسماء المدين والمورد والصنف ورقمه، ومرجع الإيداع، ورقم فاتورة الشراء ومرفقها، وتفاصيل فاتورة الدين، ومرجع التحويل وتصنيفه. فحص ارتباط تحويل الوردية بفاتورتها دون تجاوز إجماليها.
- التحويل لفاتورة الوردية لا يزيد المبيعات مرتين. تحصيل الحساب السابق لا يغير المبيعات أو نقد الدرج، والديون الافتتاحية مستقلة عن مبيعات اليوم.
- قبول كلمة مرور من ثماني خانات ورفض سبع، وتجزئة كلمات المرور، وحد محاولات دخول دائم، وإلغاء جلسات المستخدم المعطل مع حفظ تعاملاته.
- منع الموظف من قوائم الورديات والتفاصيل والنتائج والملفات والعملاء والتقارير والإدارة، ورفض الطلبات غير المصرح بها من الخادم، وحماية CSRF وOrigin.
- تسليم الموظف برد عام دون هوية الوردية أو مبالغها أو نتيجتها، وعدم إعادة عرض البيانات المسلمة في سياق الدخول.
- عدم تكرار الطلب بالمفتاح نفسه، ورفض إعادة المفتاح بجسم مختلف، ومنع تكرار المراجع، والتحقق من ملكية مرفق الفاتورة والتراجع الكامل عند فشل العملية.
- مطابقة سطور الفواتير، وربط التحصيل بدين صحيح، ورفض التسديد الزائد، وحماية الرصيد عند طلبين متزامنين لتحصيله، وتعارض التصحيح والاعتماد.
- اعتماد الجرد مع السبب، وحفظ اللقطات والنسخ والتدقيق، ومنع تعديلها أو حذفها عبر قيود قاعدة الاختبار، وترحيل **المتبقي الفعلي المعتمد**.
- منع إفساد رصيد وردية لاحقة أثناء تصحيح قديم، واستخدام تاريخ النسخة المعتمدة في التسلسل أثناء وجود تصحيح معلق، ومنع تكرار يوم الموظف بين النسخة الحالية والمعتمدة.
- إعادة إنشاء التطبيق ومحرك الاتصال مع بقاء البيانات في ملف قاعدة فعلي. إنشاء تقارير PDF من عملية Python جديدة بعد إغلاق عملية حفظ العينة.
- الأرشفة حسب تاريخ الجهاز، وفصل العجز والفائض والصافي، وتجاهل فروق النسخ غير المعتمدة، وقراءة الإجماليات التاريخية من اللقطة المعتمدة حتى عند تغيير دالة الحساب.
- تصدير CSV عربي وPDF، وتقارير الموظف الشهرية، وOutbox دائم، ومنع ازدواج الحدث والقناة، وحجز الإرسال والإقرار به، وانتهاء الحجز إلى حالة تحتاج تحققًا، وإعادة الإرسال بسبب موثق.

## قاعدة الاختبار وحدودها

تستخدم الاختبارات ملفات **SQLite مؤقتة على القرص** مع المفاتيح الخارجية والقيود والترحيلات. لا تستخدم قاعدة في الذاكرة ولا قاعدة تشغيل المستخدم. SQLite مسموحة فقط في `APP_ENV=test`؛ يرفض الإصدار 2 استخدامها للعمل التشغيلي.

اختبار `test_postgresql_migrations_decimal_and_immutable_triggers` **متخطى** لأن `TEST_POSTGRES_URL` غير متوفر، ولا يوجد خادم PostgreSQL أو Docker متاح في بيئة العمل. توليد SQL بنجاح لا يثبت أن الترحيلات أو الأقفال أو منح الصلاحيات نفذت على PostgreSQL الحقيقي. الاختبار الاختياري موجود ويستخدم مخططًا معزولًا داخل قاعدة اختبار يبدأ اسمها بـ `bin_doul_test`.

## ما لم يُنفذ

- **خادم PostgreSQL فعلي:** لم تنفذ عليه الترحيلات أو اختبارات الأقفال أو ملفات منح الصلاحيات وViews أو النسخ الاحتياطي والاستعادة. يلزم تنفيذها ببيانات اتصال بيئة التشغيل.
- **المتصفح من البداية إلى النهاية:** حاولت خدمة المعاينة بدء الخادم، لكنها لا تتضمن Python وأعادت `spawn …/python ENOENT`. أوقفت المعاينة. اختبارات HTTP الفعلية للخادم وبناء TypeScript نجحت، لكن تسجيل الدخول والتنقل وشكل الشاشات على الهاتف والطباعة لم تختبر في متصفح يعمل مع API هنا.
- **Windows:** التعليمات والسكربتات مرفقة، لكنها لم تشغّل على Windows. حزم تشكيل العربية `arabic-reshaper` و`python-bidi` مثبتة في متطلبات Windows؛ لم تتوفر محليًا. استُخدم بديل FriBidi النظامي في بيئة Linux لتوليد PDF الذي راجعناه، ولذلك لم تختبر سلسلة تشكيل العربية الخاصة بتثبيت Windows هنا.
- **n8n وSMTP وWhatsApp:** لم يستورد ملفا العمل داخل خادم n8n فعلي، ولم تُختبر بيانات اعتماد أو قالب WhatsApp أو إرسال رسالة أو بريد حقيقي. التحقق المنفذ لبنية الملفات والتعابير وAPI الدائم فقط. لا نعد بإرسال خارجي مرة واحدة تمامًا عند انقطاع الاتصال بالموفر؛ حالة `uncertain` تتطلب تحقق المدير قبل إعادة الإرسال.
- **تثبيت جديد من الإنترنت:** بيئة الاختبار استخدمت حزم Python المتاحة محليًا؛ لم يكتمل تثبيت جديد كامل من PyPI في هذه البيئة. يعتمد إعداد Windows على اتصال يسمح بتنزيل المتطلبات المثبتة الإصدارات.
- لم ينشر التطبيق خارجيًا، ولم ينقل بيانات من SQL Server قديم أو يحذف ملفات أو بيانات تشغيل.

## تحقق التشغيل المحلي

1. أنشئ قاعدة PostgreSQL اختبارية جديدة، ونفّذ ترحيلات الإصدار 2، ثم شغّل الاختبار الاختياري باتصالها.
2. أنشئ المدير الأول تفاعليًا، واستخدم قاعدة عينة منفصلة لتجربة إدخال موظف ومراجعة مدير ومطابقة ونسخة تصحيح وتصدير PDF.
3. راجع الواجهة على الهاتف، وحالة إخفاء البيانات بعد التسليم، وحسابات متعددة بصلاحياتها.
4. استورد مساري n8n وهما غير مفعلين، ثم اربط الاعتمادات والقوالب والمستلم واختبر بقنواتك قبل تفعيل الجدولة.
5. نفّذ نسخة احتياطية واستعادة إلى قاعدة جديدة، وافحص الإجماليات والمرفقات وتوقيف الإشعارات المستعادة.
