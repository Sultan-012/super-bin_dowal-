# قاعدة البيانات والتحديث والاستعادة - 2.4

قاعدة التشغيل PostgreSQL 17، مع SQLAlchemy وPsycopg 3. الجداول ذات البادئة shift_، والمقادير NUMERIC(18,2). المرجع التنفيذي `backend/shift_migrations`، وأحدث ترحيل `20261030_04`. مخطط SQL الحالي `postgresql-v2_4-schema.sql` للتفتيش أو لقاعدة فارغة فقط؛ للتحديث استخدم Alembic ولا تشغله على قاعدة قائمة. هذا الترحيل يحافظ على منع تعديل/حذف القيود الثابتة ويصنف رفض PostgreSQL برمز SQLSTATE 23000. لا يسقط أي بيانات.

مصدر الحقيقة: هوية shifts وآخر نسخة shift_versions، وتفاصيل shift_entries. اعتماد shift_approvals لقطة ثابتة للنسخة المحددة؛ التصحيح يضيف نسخة بسبب مسجل ويحتاج اعتمادًا جديدًا. تظل النسخ والاعتمادات القديمة وسجل shift_audit_logs محفوظة. الحجز العالمي على صف shift_settings داخل معاملة كل كتابة يمنع تعارض عمليات صندوق واحد. expected_version يمنع الكتابة من صفحة قديمة، وshift_idempotency يمنع تكرار طلب المستخدم، وshift_references يمنع تكرار سند مستقل أو مرجع محفوظ بين ورديات.

العملاء والديون القديمة والجرد القديم محفوظة لأجل السجلات السابقة، لكن مسارات إنشائها لا تعمل في النموذج المبسط. لا تحذف جداولها أو ترحيلاتها ضمن تنظيف ملفات الإصدار الأول.

المستخدمون لديهم أدوار admin وemployee. كلمات المرور Argon2id، وجلسات الدخول في القاعدة. المرفقات BYTEA في shift_attachments وتشملها النسخة الاحتياطية. أصل حدث الإشعار ثابت في shift_notification_events وحالة كل قناة في shift_notification_deliveries؛ الحجز والتأكيد لا يعدلان أصل الوردية. القراءة التقريرّية في PostgreSQL تستخدم REPEATABLE READ READ ONLY.

## فصل الصلاحيات

نفذ الترحيلات بحساب مالك المخطط. أنشئ `bin_doul_app` LOGIN بلا Superuser أو ملكية قاعدة/مخطط، وعيّن كلمة مروره محليًا عبر واجهة pgAdmin أو الأمر التفاعلي \password. نفذ `postgres-runtime-permissions.sql` بحساب المالك؛ اسم قاعدة المثال bin_doul. اضبط DATABASE_URL للتشغيل على هذا الحساب المحدود. لا تعط n8n وصولًا مباشرًا إلى القاعدة؛ يستعمل Bearer API محدودًا.

## النسخ الاحتياطي

أوقف n8n أثناء تبديل النسخ. من جذر المشروع ومع إضافة مجلد bin الخاص بـ PostgreSQL إلى PATH:

```powershell
.\scripts\backup-windows.ps1 -Database bin_doul -DatabaseUser YOUR_BACKUP_USER -BackupDirectory C:\BinDoulBackups
```

يطالب pg_dump بكلمة المرور عند الحاجة؛ لا تضعها في سطر الأوامر. احتفظ بالملف في وجهة منفصلة محمية وبنسخة آمنة من أسرار .env وفق صلاحيات محلية. النسخة Custom تشمل المرفقات والجداول، وتحتاج أدوات PostgreSQL متوافقة.

## الاستعادة إلى قاعدة جديدة فقط

```powershell
.\scripts\restore-windows.ps1 -BackupFile C:\BinDoulBackups\YOUR_BACKUP.dump -TargetDatabase bin_doul_restore_check -DatabaseUser YOUR_RESTORE_OWNER
```

يمنع السكربت الاستعادة فوق التشغيل ويقبل اسمًا يبدأ bin_doul_restore. ينشئ قاعدة جديدة، ثم يستعيد، ثم يشغّل after-restore-hold-notifications.sql: يلغي جلسات المستخدمين ويحوّل الإشعارات المعلقة والمحجوزة إلى تحتاج تحققًا مع تدقيق. افحص بياناتك والمرفقات والمجاميع، وأعد منح حساب التشغيل الصلاحيات؛ فخيار no-owner يجعل مالك الجداول هو حساب الاستعادة، ولا ينبغي تشغيل التطبيق بحسابه. لا تغيّر اتصال الإنتاج أو تفعل n8n قبل اعتماد النسخة المستعادة ومراجعة حالة الإرسال عند المزود.

اختبر الفحص الفعلي pg_dump وpg_restore على PostgreSQL 17.11 وقارن محتويات كل جدول قبل إجراء إلغاء الجلسات، ثم تحقق من الاستمرارية بمحرك اتصال جديد. نجح أيضًا الدخول وإنشاء مستخدم بحساب تشغيل غير مالك، ورفض DELETE/TRUNCATE/ALTER/CREATE. لم تُنفذ أغلفة PowerShell على Windows في بيئة Linux؛ تحتاج تجربة على جهازك.

## عينة واختبار منفصلان

قاعدة العينة تبدأ bin_doul_sample ولا توجّه إليها التعاملات. قاعدة الاختبارات تبدأ bin_doul_test ولا توجّه إليها الإنتاج. لا تستخدم LocalStorage أو SQLite كقاعدة تشغيل. لا توجد ترحيلات حذف أو نقل تلقائي من SQL Server للإصدار الأول؛ بياناته مستقلة تحتاج تقييمًا قبل ترحيل خاص.
