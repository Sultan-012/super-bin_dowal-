# سجل تحقق الإصدار 2.2

## اختبارات الـ Backend

من مجلد `backend`:

```text
python -m pytest shift_tests -q
39 passed, 1 skipped
```

- اختبار رفض إدخال الديون أو تسديد حساب قديم من API الجديد.
- اختبار زر اعتماد المدير: التحقق من الصلاحية والتأكيد الصريح ورقم النسخة.
- اختبار عدم تكرار الاعتماد، والتعامل مع مفتاح تكرار الطلبات.
- اختبار بقاء الموافقات والورديات التاريخية محفوظة، ومنع إعادة اعتماد وردية ذات قيود محاسبية قديمة عبر المنطق المبسط.
- اختبار إصدار PDF وCSV دون أعمدة عجز أو فائض أو ديون جديدة.
- اختبار المرفقات الاختيارية وورديتين مستقلتين في اليوم نفسه.
- اختبار سجل التدقيق وصلاحيات الموظف.

الاختبار المتخطّى يتطلب PostgreSQL اختبارية مستقلة؛ لم يُجرَ اختبار ترقية أو اتصال PostgreSQL على إنتاج فعلي.

## واجهة React

تم فحص صياغة TS/TSX باستخدام TypeScript `transpileModule` دون أخطاء صياغة. لم يمكن تشغيل `npm ci` كاملًا أو `tsc -b && vite build` بسبب عدم إتاحة تنزيل حزم npm في بيئة التجهيز. **نجاح بناء React على جهاز المستخدم شرط قبل اعتبار التثبيت مكتملًا**.

## ملاحظات نطاق التحقق

- لم تختبر أي عمليات بنكية حقيقية أو رسائل WhatsApp أو SMTP، ولم تُشغّل أدوات ترحيل على قاعدة إنتاج.
- لا يجوز التعامل مع زر «مطابقة» على أنه جرد نقدي، إذ لا تُجمع بيانات نقد معدود أو شبكة.
- يجب الاحتفاظ بقاعدة وأرشيف الإصدار السابق إذا كانت توجد ديون حقيقية سابقة تحتاج تصفية أو تسويات.
