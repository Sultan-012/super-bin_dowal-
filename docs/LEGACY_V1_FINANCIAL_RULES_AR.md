# التعريفات والقواعد المالية

## المعادلات

جميع مبالغ SQL Server من النوع `DECIMAL(18,2)`، وجميع الحسابات في Python تستخدم `Decimal`. تقبل المدخلات المالية أعدادًا صحيحة أو نصوصًا عشرية دقيقة، بمنزلتين كحد أقصى. يُرفض إدخال float في JSON، والمبالغ السالبة وغير المحدودة والمبالغ خارج المجال. واجهة المستخدم ترسل المبالغ كنصوص. سياسة توحيد النتائج هي `ROUND_HALF_UP` إلى 0.01، ولا تُقرب مدخلات ذات أكثر من منزلتين بصمت بل تُرفض.

```text
إجمالي المبيعات = المبيعات النقدية + مبيعات الشبكة + المبيعات الآجلة الجديدة

المبيعات النقدية = إجمالي المبيعات - مبيعات الشبكة - المبيعات الآجلة الجديدة

النقد المتوقع = رصيد الافتتاح
             + المبيعات النقدية
             + تحصيل الديون المستلم نقدًا
             + الإيداعات النقدية
             - المشتريات المدفوعة من الصندوق
             - المصروفات النقدية
             - السحوبات النقدية
             - المرتجعات النقدية

فرق الجرد = النقد الفعلي المعدود - النقد المتوقع

المتبقي من الدين = أصل الدين - دفعات السداد الصحيحة غير الملغاة
```

يُرفض أي إدخال يجعل المبيعات النقدية سالبة. الرصيد المتوقع قد يصبح سالبًا إذا تجاوزت المدفوعات المسجلة النقد المتاح؛ يعرضه النظام كما حُسب ولا يبدله بصفر، لكي يبقى الخطأ أو النقص في التسجيل ظاهرًا.

## مصدر الحقيقة لكل حقل

| الحقل | المصدر المعتمد | أثره في الصندوق |
|---|---|---|
| تاريخ العمل | `cash_sessions.business_date` | تاريخ أعمال الجلسة؛ ليس وقت UTC للتسجيل |
| المسؤول | المستخدم المصادق عليه عند فتح الجلسة | محفوظ كمفتاح مستخدم، وليس اسمًا يرسله المتصفح |
| رصيد الافتتاح | أول رصيد مدخل، ثم النقد الفعلي المعتمد للجلسة السابقة | رصيد بداية، لا يُعدّل بحركات صامتة |
| إجمالي المبيعات | `cash_sessions.total_sales` | الأساس الإجمالي للمبيعات قبل المرتجعات |
| مبيعات الشبكة | `cash_sessions.pos_sales` | تخصم من الإجمالي للوصول للنقدي؛ لا تدخل الدرج |
| المبيعات الآجلة الجديدة | مجموع `customer_debts.amount` الصحيحة المرتبطة بالجلسة | لا تمثل نقدًا مستلمًا |
| المبيعات النقدية | مشتقة من الإجمالي والشبكة والآجل | تزيد الدرج |
| تحصيل نقدي | حركات `cash_movements.kind=collection` المرتبطة بالسداد | يزيد جلسة استلام المبلغ فقط |
| تحصيل شبكة وتحويل | `debt_payments` حسب طريقة الدفع | يخفض الدين دون تغيير نقد الدرج |
| مشتريات من الصندوق | حركات `cash_movements.kind=purchase` المرتبطة بالفاتورة | تخصم مرة واحدة |
| مشتريات نقدية خارج الصندوق | `purchases` مع `from_drawer=false` | لا أثر لها في الصندوق |
| مصروف/سحب/إيداع/مرتجع | سجلات نقدية مفصلة في `cash_movements` | حسب نوع الحركة |
| النقد الفعلي | الجرد المسجل `actual_cash` ووقته وإصدار بياناته | ملاحظة مادية في وقت محدد، وليس رقمًا محسوبًا |
| النقد المتوقع والفرق | حساب الخادم من المصادر السابقة | للعرض والتحقق؛ لا يقبل API بديلًا محسوبًا من المتصفح |
| أرصدة العملاء الافتتاحية | `customer_debts.kind=opening` دون جلسة | لا تزيد مبيعات أو نقد اليوم |
| لقطة الإغلاق | `closing_snapshots.totals_json` المعتمدة | وثيقة تاريخية ثابتة لنتائج الحساب |

لا تُخزن مجاميع تفصيلية متعارضة في `CashSession`: فلا يوجد فيها حقل يدوي لإجمالي التحصيل أو المشتريات أو الآجل أو المصروفات. لقطة الإغلاق استثناء مقصود؛ تحفظ المجاميع المعتمدة مع وقت ومسؤول الاعتماد، ولا تُستخدم كمصدر جديد لتسجيل حركة أخرى.

## المبيعات والتحصيل

- الشبكة تعني مبيعات البطاقات وليست مبيعات نقدية.
- إجمالي المبيعات يُدخل شاملًا الشبكة والآجل، **قبل** طرح المرتجعات.
- يدخل المستخدم قيمة كل دين أو دفعة أو فاتورة مرة واحدة فقط. يظهر مجموعها آليًا في الجلسة.
- السداد ليس عملية بيع جديدة؛ لا يغير `total_sales` أو `pos_sales`.
- السداد بالشبكة منفصل عن مبيعات الشبكة. يظهر `card_collections` مستقلًا عنها.
- لا تنشأ حركة نقدية للتحويل البنكي أو التحصيل بالبطاقة.
- الأصل الموجود قبل تشغيل النظام يسجل كرصيد عميل افتتاحي من المدير فقط.
- الجزئي والكامل مدعومان. يُرفض السداد الأكبر من الرصيد المتبقي تحت قفل قاعدة البيانات.
- يجب أن يطابق تاريخ التحصيل تاريخ جلسة استلامه وألا يسبق تاريخ الدين. تاريخ الدين الأصلي يمكن أن يكون في جلسة أقدم.

## دفتر الحركات ومنع الاحتساب المكرر

الفاتورة النقدية من الصندوق تنشئ سجل `Purchase` وحركة `CashMovement` مرتبطة به في المعاملة نفسها. التحصيل النقدي ينشئ سجل `DebtPayment` وحركة مرتبطة به بالطريقة نفسها.

حساب النقد يقرأ **الحركة المرتبطة وحدها** لهذا الأثر، ولا يطرح الفاتورة أو يضيف السداد مرة أخرى إلى جانبها. فهارس فريدة مفلترة تمنع أكثر من حركة لنفس `purchase_id` أو `debt_payment_id`. يفرض قيد مصدر الحركة ألا تحمل مصدرين معًا، وألا تحمل الحركة اليدوية مصدرًا مولدًا. لا يقبل API إنشاء حركة يدوية من نوع purchase أو collection.

تُظهر جداول العمليات مصدر المعاملة مرة واحدة، مع إخفاء النسخة المولدة من جدول العرض العام؛ تبقى محفوظة ومربوطة في قاعدة البيانات. لا تُلغى الحركة المولدة مستقلة عن أصلها.

## الجرد والإغلاق

| الحالة | الرسالة |
|---|---|
| النقد الفعلي غير مدخل أو الجرد أقدم من آخر تعديل مالي | بانتظار الجرد |
| الفرق = 0 | الصندوق مطابق |
| الفرق < 0 | يوجد عجز بمبلغ القيمة المطلقة للفرق |
| الفرق > 0 | يوجد فائض بمبلغ الفرق |

الحقل الفارغ `null` مختلف عن `0.00`. الصفر جرد فعلي صالح؛ الفراغ لا يسمح بالإغلاق.

كل تعديل مالي يرفع `CashSession.version`. يحتفظ الجرد بالإصدار الذي عُدّ عنده النقد. إذا أضيفت حركة لاحقة، يبقى مبلغ الجرد ظاهرًا تحت **آخر جرد** مع تاريخه وتنبيه أنه لا يمثل النقد الحالي. تعود المطابقة إلى بانتظار الجرد حتى يُعاد العد. التحفظ يشمل العمليات غير النقدية أيضًا، لضمان مراجعة الجلسة بعد أي تغيير مالي.

مراجعة الإغلاق تحسب المتوقع والفرق في الخادم وتعيد الإصدار. اعتماد الإغلاق يعيد الحساب تحت القفل ويرفض الإصدار القديم. يجب إدخال الجرد، وتلزم ملاحظة توضيحية عند وجود فرق. يُحفظ الجرد ومسؤول الإغلاق ووقته ولقطة المجاميع وسجل التدقيق في معاملة واحدة. تتوقف إضافة وتعديل وإلغاء معاملات الجلسة بعد إغلاقها.

الجلسة التالية تستخدم النقد **الفعلي المعتمد** من السابقة، لا المتوقع. لا يجوز فتح جلسة قبل إغلاق الحالية أو بتاريخ أقدم أو مساو لآخر جلسة. يوجد قيد فريد على الصندوق والتاريخ وفهرس فريد مفلتر لمنع جلستين مفتوحتين للصندوق نفسه.

## التصحيح والإلغاء

المدير وحده يستطيع إلغاء سجل مالي مع ذكر السبب، وفي جلسة مفتوحة فقط. لا يُحذف السجل الأصلي: تُحفظ هوية الملغي ووقته والسبب، ويستبعد من المجاميع الصحيحة.

- إلغاء سداد نقدي يلغي أثره النقدي المرتبط ويعيد رصيد الدين.
- إلغاء فاتورة من الصندوق يلغي خصمها المرتبط.
- لا يمكن إلغاء دين له دفعات سداد صحيحة.
- إلغاء بيع آجل يغير توزيع إجمالي المبيعات الثابت بين النقدي والآجل؛ على المدير مراجعة إجمالي المبيعات وتصحيحه إذا كان البيع نفسه لم يقع.
- تعديل مبلغ أو طريقة دفع معاملة مفتوحة يتم بإلغائها ثم إنشاء سجل صحيح جديد، بدل الكتابة فوق أصلها.
- لا توجد عملية reversal بين أيام مغلقة في النسخة الأولى؛ لا تسجل حركة عكسية يدويًا لإخفاء سبب التصحيح.

إعادة فتح جلسة مغلقة تتطلب سببًا وصلاحية مدير، وتُمنع إذا وُجدت جلسة أحدث تعتمد على رصيدها. تبقى لقطات الاعتماد السابقة محفوظة، ويصبح جردها سابقًا حتى المراجعة والإغلاق الجديدين. لا توجد إعادة فتح ضمنية.

## التقارير والعملة والوقت

- تقارير الفترات تجمع المبيعات والتحصيل والمصروفات والحركات باعتبارها تدفقات.
- لا تُجمع أرصدة الافتتاح أو النقد المتوقع أو الجرد عبر الأيام؛ تعرض كتاريخ ورصيد في نهاية آخر جلسة أو آخر وقت جرد.
- إجمالي العجز، وإجمالي الفائض، وصافي الفرق منفصلة، ومن الجلسات المغلقة فقط.
- الجلسات المفتوحة تدخل تدفقات الفترة بصفتها غير معتمدة، ولا يدخل فرقها في مجاميع الفروق المعتمدة.
- رصيد ديون العملاء في لوحة التحكم عنوانه «الرصيد المستحق الآن» مع وقت التقرير؛ لا يدّعي كونه رصيدًا تاريخيًا بنهاية الفترة.
- الجلسات المغلقة تُقرأ في تقرير الفترة من أحدث لقطة إغلاق معتمدة. لا تعرض لقطة سابقة كاعتماد حالي بعد إعادة الفتح.
- CSV يستخدم UTF-8 BOM، مع حماية الحقول النصية من تنفيذ صيغ الجداول.
- تخزن أوقات الإنشاء والتدقيق والجرد UTC، وتعرض حسب منطقة IANA المهيأة. تاريخ العمل مستقل عن UTC.
- عملة واحدة من رموز العملات المدعومة ذات المنزلتين. يُمنع تغيير العملة بعد وجود أي سجل مالي، كما يُمنع تغيير المنطقة الزمنية أثناء جلسة مفتوحة.

## مثال القبول

| البند | القيمة |
|---|---:|
| الافتتاح | 500.00 |
| إجمالي المبيعات | 3000.00 |
| الشبكة | 1200.00 |
| الآجل الجديد | 300.00 |
| المبيعات النقدية المحسوبة | 1500.00 |
| تحصيل نقدي | 200.00 |
| مشتريات من الصندوق | 400.00 |
| مصروفات | 100.00 |
| المتوقع | **1700.00** |

الجرد 1650 يعني عجز 50، والجرد 1750 يعني فائض 50، والجرد 1700 مطابق. الفراغ يعني بانتظار الجرد. عند تحويل التحصيل 200 من النقد إلى البطاقة يصبح المتوقع 1500، ويبقى دين العميل منخفضًا بمبلغ 200 دون تغيير المبيعات.
