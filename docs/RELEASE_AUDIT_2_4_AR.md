## تغطية السلوك والأمان

شملت الفحوص مبالغ Decimal والتحويلات والمبيعات، السالب والحدود والمدخلات غير الصحيحة، أرشفة تاريخ الجهاز، منع الديون والجرد في نموذج الإصدار الحالي، القراءة التاريخية، قفل التصحيح القديم وexpected_version، رفض تعديل/حذف النسخ المالية، ذرّية المراجع والمرفقات والوردية، وتزامن تأكيدين وطلبات تسليم مكررة. شملت أيضًا رفض الوصول غير المصادق، وفصل employee/admin، وحجب حسابات الموظف بعد التسليم، وملكية المرفقات، وCSRF وOrigin، وتعطيل الحساب وإلغاء جلساته، والمحاولات المقيدة المستمرة بعد إعادة التشغيل، وCookies آمنة وHSTS وCSP في وضع الإنتاج، وحد الجسم أثناء التدفق.

فُحصت طلبات الأسماء والمراجع المخفية وNUL وUnicode غير الصالح، وحقن صيغ CSV، وPDF مزيف أو ذي JavaScript أو تشغيل تلقائي، وامتداد ملف لا يطابق محتواه. قُرئت المرفقات عبر صلاحية المدير فقط. رمز n8n لا يدير المستخدمين أو الورديات، ويحتاج رمز حجز للمهمة. حالات الإرسال غير المؤكدة تحتاج سببًا وموافقة مدير قبل إعادتها.

## إصلاحات هذا التدقيق

1. تحديث Pillow إلى 13.0.0 وpypdf إلى 6.21.4 لإزالة التنبيهات المعروفة، مع قيد اعتمادات الإنتاج المتعدية في requirements-shift-lock.txt.
2. إغلاق تجاوز حد JSON برفع متدفق بلا Content-Length صحيح، والتحقق من بنية PDF ومحتواه وامتداده وأسماء الملفات، وتحسين رؤوس أخطاء Origin.
3. عدم قص المسافات من كلمة المرور، ورفض المراجع المكونة من محارف خفية فقط والنصوص غير الصالحة قبل PostgreSQL، وحماية CSV من صيغة مسبوقة بمحارف خفية أو فراغات.
4. تصحيح رسوم العجز والفائض: مصدرها لقطات جرد قديمة فعالة، مع null عند غيابها؛ لا تُعرض أصفار توحي بمطابقة وهمية للورديات الجديدة.
5. إصلاح عبارة JSON في عقدتي واتساب، بعدما كشف تشغيل n8n الفعلي فشلها رغم اجتياز فحص JavaScript السابق.
6. إصلاح مولد العينة الذي كان يستورد مخططات أزيلت في 2.2؛ قاعدة تدريب منفصلة، دون إشعارات خارجية، ودون جرد وهمي.
7. إصلاح عرض وتصدير سجل قديم لا يحتوي مراجعة سطر من الوحدة المتوقفة، وعدم إظهار إنذار انتهاء جلسة لزائر صفحة الدخول لأول مرة، وتحمل منع تخزين تفضيل السمة.
8. إضافة ترحيل 04 وتوثيق التشغيل والترقية والاستعادة، وزر تشغيل Windows محلي بعد التهيئة.

## ما لم يُختبر أو يُعتمد

- تعذر تهيئة أداة المتصفح بسبب خطأ البيئة: `bwrap: Can't create file at /home/agent/.codex/sessions: Read-only file system`. لم تستخدم أداة بديلة لتجاوز القيد. لذلك لم يُتحقق بصريًا من كل صفحة أو مقاسات الهاتف أو طباعة المتصفح؛ اختبارات DOM لا تثبت تنسيق الشاشة.
- لم تُنفذ ملفات PowerShell/CMD أو مثبت Windows أو Docker أو إعداد HTTPS فعلي في بيئة Linux. تعليمات Windows مرفقة وتحتاج تجربة جهاز المستخدم.
- لم تتوفر قاعدة المستخدم التشغيلية؛ اختُبرت الترقية والاستعادة على بيانات اصطناعية معزولة فقط. خذ نسخة احتياطية وجرب التحديث على نسخة مستعادة من بياناتك.
- لم تستخدم حسابات SMTP أو Meta أو تثبيت n8n الخاص بك. عدد الرسائل الخارجية الفعلية صفر. صلاحية Tokens والقوالب وأرقام المستلمين وتسليم المزود وإيصالاته تحتاج فحصًا بحساباتك، دون إرسال أسرارك هنا.
- الجدولة اختبرت بتنفيذ يدوي لنسخ workflow، ولم ننتظر موعد أول الشهر الحقيقي. ملفات الاستيراد غير مفعّلة، ولا توجد موافقة ضمنية على رسائل خارجية.
- تدقيق الحزم يستند إلى قواعد بيانات الثغرات وقت الفحص، وفحص المصدر والطلبات لا يضمن انعدام كل ثغرة. لم ينفذ اختبار اختراق مستقل شامل لبنية تشغيل غير متاحة.
- اختبارات المسارات المتقاعدة في test_active_chain.py وtest_opening_reversal.py وtest_snapshot.py غير مجمعة عمدًا؛ استبدلتها اختبارات سير عمل 2.2 والأمان الحالي. كل ملفات الإصدار الأول غير النشطة خارج تقييم التشغيل الحالي وقيد قائمة الحذف.

## التسليم والموافقة

الحزمة تتضمن الكود وبناء الواجهة والترحيلات وSQL وOpenAPI و.env.example دون أسرار، واختبارات قابلة للتشغيل، وأدلة Windows والنسخ والاستعادة وn8n. تشغيلها لا يضيف أي عينات تلقائيًا. الوثائق ذات أرقام الإصدارات الأقدم باقية للمراجعة فقط.

قائمة الحذف في DELETION_REVIEW_AR.md وdeletion-proposal.json تحصر 74 ملفًا قديمًا ببصماتها وأحجامها. الموافقة المطلوبة لحذف هذه الملفات من نسخة منظّفة جديدة فقط، دون الأرشيف الأصلي أو قاعدة البيانات أو أي سجلات أو .env أو مرفقات تشغيلية. بعد الموافقة يلزم إعادة بناء وفحص المراجع المتأثرة وإصدار الحزمة المنظفة.

الملفات الآلية وتفاصيل النتائج في audit-2_4. النسخة مرشحة بسبب موافقة التنظيف والفحوص البيئية المذكورة، ولا يصح وصف الربط الحقيقي أو تجربة المتصفح غير المنفذة بأنها ناجحة.
